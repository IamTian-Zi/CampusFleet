# CampusFleet 校园多机器人路径实验

CampusFleet 是一个面向校园配送场景的机器人路径规划与调度演示项目。系统以 Python 提供服务端和网页界面，并使用 C++ 实现规划核心；校园地图扩展至 420×280 米，包含建筑、花坛、单向与双向道路、斜向通道及立体桥梁。项目支持多机器人协同规划，通过 CBS 与优先级规划协调路线，并结合等待、减速和移动行人模拟避让。网页和 React Native 客户端可模拟注册、下单、支付与配送进度查询，订单数据由 SQLite 保存。项目还提供 D* Lite 道路变化后的增量重规划演示，展示地图封闭时如何更新路线。室内楼梯、电梯及候梯行人也有简化模拟。CampusFleet 适用于课程展示与算法实验；支付、定位和机器人运动均为模拟功能，不能直接用于真实配送。

Python 3.8+ 标准库服务和浏览器界面，无需安装第三方依赖。

## 启动和操作

在此文件夹运行 `py server.py` 或 `python server.py`。服务器端调度页面为 http://127.0.0.1:8000/ ，用户客户端为 http://127.0.0.1:8000/client 。修改地图生成文件后，需要运行 `python generate_map.py` 并重启服务。

1. 选择校园交会、单向通道、双向窄道、斜向通道或路口交会场景。
2. 选择当前机器人，点击“设置起点”或“设置终点”后点击地图。圆点表示起点，方框表示终点，编号和颜色对应机器人。
3. 可添加或移除机器人，支持 1～10 台。新增机器人的默认位置需要自行检查、调整，较大的半径可能使端点进入膨胀区域。
4. 选择 CBS 或按列表顺序进行的优先级规划，设置统一半径、安全余量、最大时间步和计算时限，点击“开始规划”。“允许分段减速”默认开启，可关闭以对比相同场景。
5. 通过播放、暂停和时间轴同步回放轨迹，查看每台机器人的路径长度、到达步数、等待步数和半速步数。选中机器人后可查看当前时间区间的速度。140 毫秒播放一个模拟时间步，是加速演示。
6. “单机器人 A*”计算当前选中机器人的路线，仅对地图障碍和道路方向进行规划。

端点、临时障碍、规划方法和参数变化都会清除旧方案。原有 `POST /api/path` 接口继续提供单机器人规划，新增 `POST /api/fleet` 提供协同规划。地图数据由 `GET /api/map` 返回。

## 地图

地图从第一版的 120×80 格扩大至 420×280 格，每格 1 米。新增东区与南区建筑、环路、联络道路和花坛，保留原有桥面、带单列瓶颈和避让位的双向通道，以及两侧具有花坛边界的斜向通道。`/dstar` 提供单机器人道路封闭后的 D* Lite 增量重规划演示。

## 立体校园

默认加载“立体校园 · 五机器人”。桥面高 6 米，桥厚 0.5 米，两侧坡道各长 24 米，坡度约 14.04 度。西侧坡道从 (186,y,0) 上升至 (210,y,6)，东侧从 (250,y,6) 下降至 (274,y,0)，通行宽度由车身半径和安全余量约束。桥下 x=230 附近的南北通道可以与桥面同时通行。

勾选“启用立体路面约束”，规划状态采用 (x,y,z,t)，高度由地面或桥坡道路面确定，路面之间通过坡道口连接。桥面及坡道采用四方向相邻移动，地面采用八方向移动。坡面路程按三维长度计算，正常与半速运动都满足 1 米/秒上限。最大坡度过小会使坡道不可用，桥下净高不足会使相应地面节点不可用。临时障碍的平面位置同时约束该处地面与桥面。

车身用竖直圆柱近似。在每个时间区间内，先求两车高度占用可能重叠的时间范围，再在此范围内求水平最小间距。桥上桥下具有足够高度差时可并行，坡道汇入口继续接受碰撞检查。机器人到达后持续占据终点体积。

“三维投影”和“俯视编辑”读取同一轨迹和时间轴。三维视图采用固定等轴测投影，高度放大 2.5 倍，车身标记具有最小显示尺寸。编辑端点时切换俯视图，选择地面或桥面/坡道，再点击位置。桥面端点可以位于地面景观河上方。

当前以分层路面与竖直圆柱描述地面机器人，坡面车身俯仰、加速度、制动距离和最小转弯半径仍需进一步建模。投影绘制采用面片排序近似遮挡。原单机器人二维接口继续接收 [x,y]，立体规划通过 /api/fleet 的 use_terrain=true 接收 [x,y,z] 或将 [x,y] 作为地面点。

`generate_map.py` 是地图定义源，`campus_map.json` 是生成结果。任何接触障碍多边形的格子都会标为障碍，界面直接绘制同一组栅格。半径与安全余量沿用第一版的保守整格膨胀，可能使窄道比几何外观更窄。默认参数下，南区双向通道中具有单格宽瓶颈和侧向避让空间。

`lanes` 中的 `cells` 指定道路规则区域，`direction` 指定单向前进方向。单向区域的进入和离开也受方向约束，移动向量与方向向量点积必须为正。朝前的斜向移动允许执行，原地等待允许执行。双向通道未附加方向约束。其余未标为障碍的背景仍可通行。

## 规划模型

所有机器人使用相同半径 r 和安全余量 m。地图构成有向图，状态为 `(x, y, t)`，动作包括八方向移动与等待。斜向动作禁止穿过障碍角隙。

每个模拟时间步为 √2 秒。正常移动用一个时间步走完相邻格，直行速度为 1/√2 米/秒，斜行速度为 1 米/秒。允许减速时，同一条边也可以用两个时间步走完，速度降为对应方向正常速度的一半，中间时刻位于半格位置。这是路线与分段速度的联合搜索，等待是独立的零速度动作。

半速动作开始后必须连续走到相邻格，搜索状态仍记录整数格端点与到达时间，输出轨迹按统一时钟补齐半格位置。每一个时间区间都执行连续运动碰撞检查，CBS 的约束也作用于半速动作的中间区间。`slow_steps` 是半速运动占用的时间步数，一次半速跨格计两步；`speed_profile_mps[t]` 是第 t 到 t+1 步间的速度，终点之后为零。旧接口请求默认关闭减速，前端协同规划显式开启 `allow_slowdown`。

机器人在动作边界允许瞬时变速和转向。当前是离散速度档位，尚未加入加速度、制动和转弯半径限制。路线长度仍按直行 1 米、斜行 √2 米统计，减速会改变到达时间。

机器人间的最小中心间距为 `2r + m`。对每对机器人，计算整个时间步内相对直线运动的最小距离，发现同格、对向交换、对角交叉和圆盘间距不足等冲突。即使半径为零，中心重合也禁止。到达后持续占用终点，同一起点或过近终点会在请求阶段拒绝。

CBS 首先独立规划，再找到最早的冲突，对冲突双方分别建立禁止该时刻执行该次移动的分支，重新规划受约束的机器人。高层按总到达步数、总等待步数、总路径长度依次排序，低层用时间维度 A*，反向搜索给出遵守方向规则的最少剩余步数。同到达时间的路径优先减少停车等待，再比较长度。搜索缓存复用相同机器人及约束下的结果。

优先级规划依次为机器人建立时间预约，后续机器人避开先前轨迹和长期占用的终点。列表顺序可能影响成功率和等待量。

计算受每台最大时间步、用户计算时限，以及内部 500000 个时间状态扩展和 1000 个 CBS 高层节点限制。CBS 会先保存通过完整冲突检查的优先级可行方案。达到限制时，如存在此方案则返回它，并在 `warning` 中说明尚未证明最优，`used_method` 标为 `priority`；如没有可行方案，则返回“本次未找到方案”。不据此断言地图无解。计算时限覆盖规划搜索，不包含地图膨胀和网络传输。复杂拥堵下的 10 台机器人可能达到限制。

## 验证

运行 `python -m unittest -v test_planner`。测试包含全部预设在两种协同方法下的合法性与连续移动冲突检查、单向进出规则、禁止穿角、到达后占用、必须等待的十字窄道、封闭窄道无解，以及 HTTP 接口与无效参数。变速专项覆盖半速替代停车、半速动作中间时刻的约束，以及五机器人轨迹安全、速度上限和距离一致性。

模拟使用虚构二维地图，采用统一时间步和确定性运动，实际机器人运动学、定位误差和传感器动态障碍尚需后续建模。
